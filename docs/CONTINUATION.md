### 비교 계약

- `params_hash`는 사전계산 파라미터의 해시다. 사용자가 선택한 렌즈와 표본 보행 시간을 대신하지 않는다. `comparisonMismatch`로 모두 검사한다. 누락된 옛 표본은 제외하되 저장 데이터를 삭제하거나 덮어쓰지 않는다.
- 설계 비교 출발점은 boundary의 경계 상자 중심에 가장 가까운 **기존 네트워크 노드**다. 전후 동일 노드·시간·속도를 쓰고 `ped_link`·`barrier`는 설계 후 권역에 반영한다. 출발점은 화면 좌표와 지도 점으로 공개한다. 대상지를 대표하는 위치인지는 사용자가 확인해야 한다.
- `DesignResult.before/after` = 대상지, `beforeBuffer/afterBuffer` = 기존 버퍼 범위. 새 `comparison.results[5|10]` = 보행권의 전후 지표와 `beforeCells/afterCells`. `currentTarget()`은 이 보행권의 `after`만 사용한다.
- 접근성 갱신 셀 = 기존 버퍼 ∪ 전후 보행권. 서비스 수요는 지역 전체 인구를 사용한다. 공원 대표점으로 후보를 거르지 않는다. 공간이 길면 대표점이 멀어도 입구가 가까울 수 있기 때문이다.
- 새 보행권 전후 비교는 같은 시간의 권역을 비교한다. 통로 변화로 포함되는 주민·땅이 바뀔 수 있으므로 고정 주민 집단의 효과 추정과 다르다. 대상지·버퍼 표는 고정 공간 전후 비교용으로 남긴다.
- 건강 라벨은 관측 동네에만 붙는다. 설계안은 관측된 건강 결과가 없으므로 예측값처럼 제시하지 않는다.
